# 내 하네스 설계표 — 사례에서 내 업무로 가져오기

> 빈칸부터 쓰지 않는다. 아래 다섯 유형 중 내 업무와 **가장 비슷한 것 하나**를 골라, 「예시」 값을 내 업무 말로 바꾼다.
> 모르는 칸은 예시 그대로 둔다. 고객명 · 실제 수치 · 시스템 주소는 가린다.
> 실습 자료(`labs/work_harness`)의 Skill이 각 유형의 실제 하네스다.

## 1. 유형 고르기

| 유형 | 실습 예시 (work_harness Skill) | 이런 업무라면 |
|---|---|---|
| 문의 응대형 | 사내 문의 답변 (`inquiry-answer`) | 고객 클레임 1차 답변 · 시스템 사용 문의 · 사내 헬프데스크 |
| 문서 추출 · 계산형 | 사양서 → 견적 (`spec-quote`) | 발주서 검토 · 계약 조항 추출 · 정산 |
| 기록 → 보고서형 | 점검 기록 → 주간 보고서 (`weekly-report`) | 장애 주간 보고 · 생산 실적 보고 · 품질 리포트 |
| 비교 · 검토형 | 규정 개정 비교 (`doc-diff`) · 코드 리뷰 | 계약 변경점 · 설정 변경 리뷰 · 문서 개정 검토 |
| 정리 · 작성형 | 회의록 → 할 일 (`meeting-actions`) · 안내 메일 (`mail-draft`) | 회의 후속 조치 · 공지 · 협력사 메일 |

내가 고른 유형: ____________

## 2. 값 바꾸기 (예: 기록 → 보고서형)

| 칸 | 예시 · 주간 설비 점검 보고서 | 내 업무 |
|---|---|---|
| Skill 이름 · 언제 쓰나 | weekly-report · 점검 기록으로 보고서를 만들 때 | |
| 입력 | 점검 기록 엑셀 · 점검 기준 | |
| 결과 양식 | 요약 3줄 · 정비 요청 · 경고 · 확인 필요 | |
| 판단 기준 | 진동 7.1 초과 경고 · 이틀 연속 → 정비 요청 | |
| 막을 것 (Hook) | 원본 수정 · 외부 메일 발송 | |
| 사람 확인 | 발송 전 팀장 | |
| 잘했다의 기준 (평가) | 누락 0건 · 수치가 원본과 일치 | |
| 자주 나는 실수 | 빈 값을 0으로 · 경계값 7.1 | |

다른 유형을 골랐으면 `labs/work_harness/harness/.claude/skills/<Skill 이름>/SKILL.md`를 열어 「예시」 칸을 그 내용으로 채운다.
