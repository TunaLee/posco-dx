# 코드 리뷰 절차

1. 리뷰할 파일 목록을 먼저 만든다 (`shop/` · 바뀐 파일).
2. 파일마다 네 가지로 본다 — 보안(비밀 키 · SQL 조립 · 권한 · 민감 정보 로그) · 버그(경계값 · 예외 무시 · 상태) · 성능(반복 쿼리) · 테스트(빠진 경우).
3. 보안이 의심되면 `security-reviewer` Agent 에게 맡기고 결과만 받는다.
4. 지적마다 파일:줄 · 근거 코드 한 줄 · 고칠 방법 한 줄. 근거가 없으면 쓰지 않는다.
5. `out/review.md` 에 아래 형식으로 저장하고, 대화에는 요약 세 줄만.
6. 코드는 고치지 않는다 (리뷰어는 지적만).

## 형식
| 심각도 | 파일:줄 | 종류 | 지적 | 고칠 방법 |
- 심각도: 🔴 즉시 · 🟡 다음 PR 전 · ⚪ 참고
- 맨 위에 요약 한 줄: 파일 N개 · 🔴 N · 🟡 N · ⚪ N
