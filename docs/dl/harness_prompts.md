# 하네스 만드는 요청문 (말하듯이)

〈 〉 안만 내 업무로 바꾸거나, 아예 내 말로 바꿔도 된다. 목표 · 범위 · 확인 방법 · 하지 말 것 네 가지만 들어가면 된다.

## CLAUDE.md

```
이 프로젝트의 CLAUDE.md를 만들어 줘. 모든 작업에 공통인 원칙만 짧게, 30줄 안으로.
결과는 〈out/작업명/〉 에 파일로 남기고, 〈원본 폴더〉 는 고치지 말고,
숫자 · 이름 · 날짜는 원본에 있는 것만 써서 없으면 「확인 필요」로 표시하고,
근거(파일명 · 조항)를 꼭 달고, 〈승인 · 환불 · 외부 발송〉 같은 건 담당자 확인으로 넘기게 해 줘.
작업별 절차는 여기 말고 Skill로 빼 줘.
```

## Skill

```
〈업무 이름〉 을 Skill로 만들어 줘. 〈언제 쓰는지〉 할 때 알아서 쓰이게 설명을 달아 주고,
본문에는 순서, 판단 기준 〈기준〉, 결과 양식 〈양식〉, 하면 안 되는 것을 넣어 줘.
긴 규정은 같은 폴더에 참고 파일로 빼 두고, 다 만들면 예시 입력 하나로 시험해서 보여 줘.
```

## Hook

```
〈막을 것〉 은 Hook으로 막아 줘. 〈허용할 것〉 은 그대로 두고.
막을 때는 왜 막았는지 한 줄 보여 주고, 외부 패키지는 쓰지 말아 줘.
다 만들면 막아야 할 예 다섯 개, 허용해야 할 예 다섯 개로 직접 시험해서 결과를 표로 보여 줘.
```

## 검증 Agent

```
결과물을 원본과 대조하는 읽기 전용 검증 Agent를 만들어 줘.
숫자 · 날짜 · 빠진 항목 · 지어낸 내용을 찾아서 통과 / 실패와 근거(파일:줄)만 알려 주고, 고치지는 않게.
CLAUDE.md에도 「끝내기 전에 검증 Agent에게 대조를 맡긴다」를 넣어 줘.
```

## 평가

```
이 업무를 채점할 수 있게 평가 문항을 만들어 줘.
과거 사례 〈5〉건에 까다로운 경우 〈2〉건을 더해서, 각각 입력 · 기대 결과 · 꼭 들어갈 말 · 들어가면 안 되는 말을
eval/cases.jsonl 에 넣고, O / X로 채점하는 스크립트도 만들어 줘. 지금 하네스로 한 번 돌려서 점수를 보여 줘.
```

## 고치기

```
방금 채점에서 틀린 걸 보고 하네스를 고쳐 줘.
원인이 절차면 Skill, 공통 원칙이면 CLAUDE.md, 꼭 막아야 하는 거면 Hook을 고치고,
무엇을 왜 바꿨는지 한 줄씩 남겨 줘. 다시 채점해서 전후 점수도 비교해 줘.
```

## 한 번에

인터뷰 · 설계 · 생성 · 시험까지 한 번에 하려면 메타 하네스(`meta_harness/`, 강의 Ch8)를 쓴다.
